# ros2_fp implementation plan

**Goal:** Create `~/Documents/ros2_fp/src` with the reference dummy arena and rover,
launchable using ROS Humble and Gazebo Classic without sourcing simulasi_rover.

**Architecture:** Retain the four ROS package names so mesh URIs and Livox message
types stay compatible. Copy source assets, not build/install output. Resolve scan
patterns through xacro's package index, and register Gazebo resource/plugin paths
before starting Gazebo. Use the existing hardware driver as the message provider;
no hardware node is launched.

**Constraints:** Preserve the reference world and robot geometry, drive, and
sensors. Do not modify the reference workspace. Exclude navigation, mapping,
controller applications, and previously generated artifacts.

## Tasks

- [ ] Copy the robot, dummy world, Livox plugin, driver source, and upstream licenses.
- [ ] Prepare package manifests, portable scan path, launch options, and CMake
  linking against installed Protobuf/Boost instead of obsolete version names.
- [ ] Build in a clean environment containing only `/opt/ros/humble`.
- [ ] Verify installed meshes, scan pattern, package isolation, and plugin library.
- [ ] Run headless Gazebo: assert spawn success, sensor data, and odometry response
  to `/cmd_vel`; stop only the test's own processes.
- [ ] Copy sources to the requested Documents directory, rebuild there, and repeat
  verification so generated installation files contain the final workspace path.
- [ ] Document launch/build commands and report any runtime limitations.

## Review focus

Missing external workspace, absolute CSV paths, stale Boost/Protobuf library
versions, missing Gazebo media paths, and plugin/message dependencies must be
covered by the build, resource tests, and headless integration check.
